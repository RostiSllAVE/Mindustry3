## Cause and implementation

Native `Schematics.create` reads `Vars.world` (Z0). Elevated building input deliberately bypasses native `DesktopInput` to avoid duplicate construction, so its rectangle-selection lifecycle also needed an elevated path. The existing picker, construction-surface resolver and structural validator are retained.

- `LayerSchematicInput` owns copying/pasting inside FPV Build Mode. It uses the registered native schematic-selection binding (F by default, also works with Ctrl+F). The first visible physical hit chooses the source floor; a manually locked floor overrides it. One projected rectangle remains on that floor until release. Normal block selection can be active when copying starts. Clipboard gestures consume input before inspection, possession, dismantling and ordinary placement.
- Z0 extraction still calls native `Schematics.create`. Upper extraction visits actual components on the selected floor, deduplicates multi-tile footprints and crops their complete bounds. Empty cells remain empty and underlying Z0 buildings are not consulted. Native schematic serialization creates independent supported configuration values. There are no inventories, ammo, health damage or operational-instance snapshots in the clipboard.
- Clipboard storage, `lastSchematic`, `selectPlans`, library/import/save, native rotation/flip and `.msch` encoding are reused. Optional platforms use an ordinary `fpv-platforms` tag containing two-dimensional coordinates on this one floor; it contains no source layer or XYZ volume. Vanilla readers can still read the block portion. Platform placeholders are removed before native ground queues or ordinary 2D input can handle them.
- Paste positions use the existing nearest physical construction-surface resolver, or an explicitly locked plane. A click freezes its target layer and anchor until release. Repeated tap samples and stationary holds cannot produce more stamps or climb automatically onto newly built blocks. Rotation includes native multiblock offsets and relative configuration transforms.
- The full translucent preview uses existing textured hologram geometry, depth testing, frustum culling and batches of at most 256 ghosts. This is a separate clipboard overlay, preserving the current single-block renderer and its limits. Validity is computed on a temporary world with the existing structural solver, then each actual construction is revalidated on the authority. Missing support, intersections, occupied cells, load limits, team/core protection and host Free permission remain enforced. Invalid entries are visibly marked/skipped; the valid count and reason are shown.
- Ground paste invokes native `flushPlans`, `Block.onNewPlan` and the normal unit build queue. Elevated paste carries a bounded native `.msch` payload through the existing authenticated reliable construction channel. Server jobs are unpaid plans: build speed/time/cost multipliers apply, completion uses ordinary PLACE validation/payment, unavailable resources wait, and permanent invalid positions are skipped. Configurations/internal links are applied only to newly created IDs after the job finishes. Power links also pass team/range/server configuration validation. Existing sequence/epoch checks reject reliable replay before enqueueing; queued duplicate cells are additionally rejected.

## Controls

1. Enter Tab / Build and aim at the desired floor. Use the left-side floor lock for an explicit plane when necessary.
2. Hold Ctrl+F (or the native configured selection key), drag a rectangle and release F.
3. Move the complete preview to another valid floor. Use the existing rotation and flip controls.
4. Click LMB once to queue the valid blocks. Release before another stamp.
5. RMB or Escape dismisses the uncommitted clipboard. The existing clear-building binding clears native plans and cancels the player's unpaid upper paste jobs. Tab retains the clipboard while removing its flight-mode preview.

## Limits

- One floor per scheme. No volumetric copy, source-floor preservation or cross-floor logistics-link cloning. Only connections whose endpoints are both copied on this floor are retained. An uncopied endpoint is omitted/disabled; existing separate cross-floor connections are not created automatically.
- Elevated requests are limited to 128×128 tiles, 4096 combined blocks/platforms and a 16 KiB compressed native payload. Expansion/count/footprints and native JSON tag shapes are bounded before server decoding. Unsupported native/mod configurations are omitted with a warning during upper copying; imported unsupported configurations are rejected. Supported values include ordinary item/liquid/unit/block choices, native integer/bool/text settings, relative Point2 links, power Point2 arrays, bounded integer arrays and compressed logic/canvas configurations accepted by existing adapters. Custom arbitrary objects, oversized data and arbitrary object arrays are unsupported.
- Upper queued jobs are not a saved or replicated native unit-plan list. Completed buildings replicate/save normally; unpaid unfinished jobs are cancelled on world restore/reset, death, team change or changing the builder unit. This cannot refund/mint resources because no pending entry has been paid. Their build progress follows world time and the unit's build speed; the native ground-queue pause toggle applies to native ground plans, not this separate upper job queue. Clear-building cancels the upper queue.
- Internal configuration is applied after the selected valid job entries finish, so an unfinished job waiting for resources has not yet configured its completed entries. Upper platforms pasted onto Z0 are omitted from the native ground queue and shown invalid.
- Material/permission/support changes after preview are revalidated during actual completion; a formerly valid entry may be rejected then. The temporary structural preview changes no map tiles, native building instances or simulation state.
