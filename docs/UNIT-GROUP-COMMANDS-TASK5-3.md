## Cause and scoped fix

The FPV input policy suppresses native `commandMode`, `commandQueue` and selection bindings during flight; the pointer is captured and native command overlays are disabled. Build's custom interaction branch also cancels native `commandRect`. Simply unblocking Shift would leave flight firing/mouse capture active and the native rectangle would still query a2D world rectangle under a perspective camera.

`FpvUnitCommands` adds a dedicated command interaction adapter alongside the existing builder. It uses the existing canonical `World3DAdapter` unit positions, solid-world traces and cylinder math for unit picking/occlusion; surface destinations reuse **BuildingMousePicker** and the existing renderer interaction pick. It does not replace terrain picking, construction, physics, combat or any unit AI.

- In flight, the native command binding (**Shift by default**) enters/toggles commands according to Mindustry's **commandmodehold** setting. Where the native boost binding conflicts with command mode for a boost-capable pilot, the existing boost behavior remains; use **F10** for commands.
- **F10** explicitly toggles commands from either Flight or Build. In Build, Shift retains its existing linking modifier. **Tab** ends the command gesture and performs the existing Flight/Build transition. Command mode preserves the previous Build/time-scale state.
- Mouse capture/look, movement axes, pilot firing, possession and placement are gated while commands own the pointer. The possessed unit is held/stabilized; only that same unit remains possessed. Stored block/rotation are hidden while commanding and restored on exit. Existing committed build queues remain active and are never cleared or charged again.
- A held button on exit is fenced **until release**, without a timer/cooldown. In native hold mode, releasing Shift during a selection drag defers exit until the mouse release so the rectangle can complete safely. A fresh command-key edge after cancellation is accepted immediately.
- **LMB click** follows vanilla toggle selection; **LMB drag** replaces the selected group with visible friendly commandable bodies in the screen rectangle. Units with the same native XY but different physical heights project to different screen positions. Terrain/buildings/platforms and native fog gate visibility.
- **RMB** issues a move order or an attack on the visible enemy. The native **commandQueue** binding (default MMB) queues orders. RMB during an unfinished rectangle cancels that rectangle without an attack. **Esc** cancels a rectangle; Esc without a rectangle clears selection and exits, consuming the menu binding for that frame.

The ordinary native `input.selectedUnits` is the only selected-group collection. Validation uses actual native `isCommandable`, `allowCommand`, validity and team/fog metadata. The UI shows a screen-space rectangle and selected-unit hexagons at real XYZ projections; native command panels are available. Group orders use the existing `Call.commandUnits` endpoint, native200-unit batching, queue/finalBatch flags and **unchanged CommandAI/server permissions**. Core unit types follow native controller metadata, without a new blacklist. Selected groups and issued orders survive leaving commands and returning to the2D camera.
